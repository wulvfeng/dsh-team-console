# dsh-team-console — DSH Agent Teams 监控面板

> ⚠️ **不要把占用 `4318` 端口的进程杀掉。**
> 插件本体运行在 DSH 主程序进程内，`4318` 的监听者就是 `DeepSeek Harness` 自己；
> 按端口 `Stop-Process` 会直接杀掉主程序（表现为「应用无法启动或已意外停止」）。
> 想停掉服务，请关闭插件，或用 `node lib/start.mjs 4321` 换个端口跑独立版。

把 **Lead 与每个 teammate 的会话流、共享任务板、成员实时状态** 放进一个本地网页里。
数据全部来自 DSH 自己的会话日志，不依赖任何私有接口，也不影响模型请求。

## 安装（所有人可用）

> **npm 包尚未发布**（registry 上还是 404），当前请直接用 GitHub 源码安装；发布之后 `dsh plugin --profile web add dsh-team-console` 会同样生效。

```bash
dsh plugin --profile web add github:wulvfeng/dsh-team-console
```

桌面版把 `--profile web` 换成实际 profile（例如 `desktop`）。仓库已提交构建产物，无需放行构建脚本。装完重启 DSH，左侧栏「团队」入口即出现；用这种方式**不需要**运行 `install.mjs` 或手工改 `cordis.patch.yml`。本地开发/离线时也可以用下一节的 `node install.mjs` 直接装源码目录。

验证：`dsh plugin --profile web list` 应列出 `dsh-team-console`。

## 你会看到什么

| 区域 | 内容 |
| --- | --- |
| 成员列表 | 名称、阶段（provisioning / active / failed）、模型、**此刻在做什么**（"正在调用 run_code" / "正在思考" / 空闲 + 多久之前）、工具调用数、消息数 |
| 任务板 | 任务 id、标题、状态（可开始 / 被依赖阻塞 / 进行中 / 已完成）、负责人、依赖、写入范围；点任务直接跳到负责人的会话 |
| 会话流 | 逐条还原某个会话：用户消息（我派给他的任务）、助手回复、**每一次工具调用的名字 / 参数 / 结果**、思考过程（折叠）、团队事件（成员加入、任务变更） |
| 顶部 | 团队切换、实时状态、是否显示运行时上下文注入、自动跟随滚动 |

Lead 会话与每个成员会话看的是同一套渲染，所以"我让他做了什么 / 他回了什么 / 他调了什么工具 / 产出了什么"都在一屏里。

## 快速开始（不装插件，立即可用）

```bat
start.bat
```

浏览器会打开 `http://127.0.0.1:4318/`（实际地址以控制台输出为准）。端口占用分两种：Host 插件跑在 DSH 进程内，4318 被占会**自动 +1 顺延**；独立运行 `node lib/start.mjs` 时，如果端口被**其它程序**占用，会提示换端口并以退出码 2 结束（0.7.3 起的防误杀策略），不会自己去抢端口。
也可以手动：`node lib/start.mjs 4318 --open`。

## 看效果：示例团队（demo）

不想等真实团队跑起来、或者只是想先看看样式长什么样，用内置的示例数据：

```bat
npm run demo
```

2. 用**真实的数据层**起一个只监听 `127.0.0.1` 的实例（默认 4320，避开插件的 4318）；

> DSH 面板里读的始终是 Host 提供的真实数据。

## 装成 DSH 插件（随 DSH 启动自动运行）

```bat
node install.mjs
```

默认装进 `%USERPROFILE%\.dsh\profiles\desktop`，做四件事（改文件前都留有 `.team-console-backup-*` 备份）：

1. 在 `profile/node_modules` 建目录联接 `dsh-team-console`（不需要 pnpm）
2. 在 profile `package.json` 的 `dependencies` 登记 `link:<本目录>`
3. 在 profile `package.json` 的 `dsh.profile.bundles` 注册 `dsh-team-console`（DSH 只加载 bundles 里列出的组合包；缺这一步，`cordis.patch.yml` 的插件行不会生效）
4. 在 profile `cordis.patch.yml` 追加 `team-console` 插件行（按行匹配，可重复执行）

脚本整体幂等，中途失败会回滚本次新建的联接与改写的文件。**装完重启 DSH**，Host 启动时就会拉起面板；`http://127.0.0.1:4318/` 常驻。

指定其它 profile：`node install.mjs --profile C:\path\to\profile`。

## 在 DSH 界面里使用（v0.3，左侧栏）

> 面板固定在左侧栏导航行，点一下就在主区域打开：**团队**。
> 创建团队、派活、催进度 **不经过面板** —— 仍然是在任意会话里用自然语言说；面板只负责自动显示。

1. 重启 DSH（Host 插件在启动时加载，`cordis.patch.yml` 已经装好）。
2. 刷新 Web 页面，左侧栏出现「团队」图标/行。
3. 没有团队时显示空状态提示；一旦会话里出现 `spawn_teammate`，成员、任务、会话流自动出现。

面板内容与独立网页一致（同一套只读 API）：

- 成员：阶段、模型、**此刻在做什么**（正在调用哪个工具 / 正在思考 / 空闲 + 多久前）、工具与消息计数
- 任务板：状态、负责人、依赖链、写入范围；点任务跳到负责人会话
- 会话流：消息 / 回复 / 每次工具调用（名字、参数、结果）/ 思考过程 / 团队事件

数据通道：Host 半侧在进程内启动只读 API（默认 `127.0.0.1:4318`，占用则顺延），面板从 `4318..4337` 依次探测；只读 GET 只对回环 Origin 回显 `Access-Control-Allow-Origin`（任意网站无法读取），服务只监听回环。

## 配置

`cordis.patch.yml` 里的 config：

```yaml
- id: team-console
  name: "dsh-team-console"
  config:
    port: 4318          # 监听端口（127.0.0.1，端口占用自动 +1）
    # sessionsRoot: ... # 会话目录，默认 %USERPROFILE%\.dsh\sessions
    maxAgeDays: 14      # 团队列表扫描多久以内的会话
```

## 原理

- DSH 把每个会话写成 `<sessions>/<workspace>/<id>/session.v4.jsonl.zstd`：**追加写的多 frame zstd**，内容是 JSONL 事件流。
- 本插件负责：定位会话文件 → 逐 frame 解压 → 解析事件 → 组装团队模型（`lib/sessions.js`、`lib/team.js`）→ 通过本地 HTTP + 前端渲染（`lib/server.js`、`public/`）。
- 团队关系来自 lead 日志里的 `team/member` 与 `team/task` 事件；子会话通过 `subagent/catalog` 与自身 `parentSession` 关联；当未开启 Team 模式时，也会通过子会话的 `parentSession`（`session-tree` 兜底路径）自动还原成员与会话流。
- 磁盘读取按 `(mtime, size)` 缓存，2 秒轮询只解码发生变化的那一份；JSON 响应超过 4KB 走 gzip。
- 插件**不注册任何工具 / 提示词 / 会话事件**，模型看不见它，KV cache 不受影响。

## 是否需要开启 DSH「启用智能体团队协作」

**不强制开启。** 只要会话中通过 `subagent` / `subagent_fork` 派生了子智能体，本插件都能自动识别并展示；但是否在 DSH 根会话的模型菜单中打开**「启用智能体团队协作」**，展示完整度有所不同：

| 功能与展示项 | 未开启（走 `session-tree` 兜底路径） | 已开启（走 `team/*` 完整主路径） |
| :--- | :--- | :--- |
| **团队列表自动识别** | ✅ 自动识别（通过子会话 `parentSession` 聚合） | ✅ 自动识别（通过 `team/member` / `team/task`） |
| **成员名册与实时状态** | ✅ 显示成员、模型、当前动作（思考/调用工具/空闲） | ✅ 完整显示 |
| **成员会话流与工具调用** | ✅ 完整还原每个成员的提示词、回复与工具步骤 | ✅ 完整还原 |
| **共享任务板（Task Board）** | ❌ 为空（未开启时 DSH 不暴露 `team_task_*` 工具，无 `team/task` 事件） | ✅ 完整展示任务状态、负责人、依赖阻塞 `blockedBy` 与写入范围 |
| **多轮请求分组（Requests）** | ⚠️ 归并为单组「本次协作」 | ✅ 按每轮用户提问精确分组 |

> **使用提示**：
> - 日常使用多 Agent（包括配合 `dynamic-multi-agent`、`supervisor-worker` 等动态编排 Skill）时，即使不开开关，面板也能实时看到所有子成员与执行过程；若需要**共享任务板**和**按轮次分组**，请在根会话菜单开启**「启用智能体团队协作」**，并确保模型在拆解任务时调用 `team_task_create` / `team_task_update` 同步任务状态。
> - 若任务被判定为**单 Agent** 执行（未派生任何子会话），本插件不会将其作为团队展示。

## HTTP API

| 路径 | 说明 |
| --- | --- |
| `GET /api/teams` | 所有含团队的 lead 会话（标题、成员数、未完成任务数） |
| `GET /api/team?lead=<id>` | 团队名册 + 任务板 + lead 摘要（含 activity） |
| `GET /api/session/<id>?limit=200` | 规范化会话流（user / assistant / reasoning / tool / team / context） |
| `GET /api/health` | 存活检查与配置回显 |

## 已知限制

- **只读**：不能在这里 spawn / 中断 / 改名成员，也不能改任务；这些仍然通过对话做。
- **任务单负责人**：DSH 的共享任务板一个任务只有一个 `ownerName`；多人协作的任务请拆成多个任务并用 `blocked_by` 串起来，面板会显示依赖与各自的进行状态。
- **独立页面**：`start.bat` / `node lib/start.mjs` 打开的是不含 DSH 外壳的独立网页；DSH 内请用左侧栏「团队」面板（0.3 起提供），两者读同一套只读 API。
- **成员活跃度**：成员超过 10 分钟没有任何新事件时，活动标签会显示「（10 分钟无新事件）」并视为非活跃（stale），用于区分「空闲」与「可能已崩溃/被中断」。
- **语言**：`locale/*.json` 仅用于插件市场/管理器的标题与描述元信息，面板 UI 目前只有中文。
- **打开方式**：请在浏览器里用 `http://127.0.0.1:<端口>` 或 `http://localhost:<端口>` 打开 DSH 面板；用局域网 IP/其它域名打开时，面板无法跨源读取本地只读 API（这是 CORS 收紧后的安全取舍，避免任意网页读取你的会话记录）。
- **历史窗口**：默认只列出 14 天内有更新的会话；旧团队不会出现在下拉里。

## 目录结构

```
dsh-team-console/
  package.json        cordis 插件清单（dsh.bundle.patch）
  cordis.patch.yml    插件行
  install.mjs         装入 profile（junction + dependencies + dsh.profile.bundles + patch 行）
  start.bat           独立启动（不依赖 DSH）
  lib/
    index.js          cordis Host 插件入口（启动服务、随 fiber 释放关闭）
    server.js         本地 HTTP 服务 + 静态资源 + JSON API
    sessions.js       多 frame zstd 解压、会话定位、事件解析缓存
    team.js           团队模型、成员活动推导、会话流规范化
    start.mjs         独立启动器
  public/
    index.html        页面骨架
    app.js            渲染与轮询（无构建、无依赖）
    style.css         深色主题样式
```

## 卸载

1. 删掉 profile `cordis.patch.yml` 里的 `team-console` 行（或恢复 `.team-console-backup-*`）
2. 删掉 profile `node_modules\dsh-team-console` 联接
3. 从 profile `package.json` 的 `dependencies` 移除 `dsh-team-console`
4. 从 profile `package.json` 的 `dsh.profile.bundles` 移除 `dsh-team-console`（否则 DSH 仍会尝试加载它）

## 版本

### 0.2.0 — 独立审查后的加固版

审查员（`reviewer-1`）报的问题已全部处理：

| 级别 | 问题 | 修复 |
| --- | --- | --- |
| P0 | 同步全量解压跑在 HTTP 回调里（4.5MB 日志 291ms / 堆 +98MB） | 改成**增量解码**（只解压上次之后的新 frame）+ 源字节预算缓存（12MB / 12 文件）+ 团队扫描改**异步分片**（每 2 个文件让出事件循环）；实测冷启 552ms（异步）、热 1.7ms |
| P0 | dispose 竞态：端口重试期间 close() 后服务变孤儿 | `disposed` 标志 + 记录所有监听实例，listen 回调内自检自杀；实测立即 dispose 无泄漏端口 |
| P1 | 端口全忙时 ready 静默失败 | `ready` 8s 后 reject 并上报 logger，插件侧 catch 不再吞掉 |
| P1 | 魔数切帧会误判、坏帧静默丢、未检测 zstd 支持 | 候选边界**失败合并重试**（最多 8 段）+ 显式检测 `zstdDecompressSync` + 坏帧计数 |
| P1 | user / reasoning 文本未截断（单条 57KB） | 统一 6KB 截断 |
| P1 | `buildTeamIndex` 每次全量重扫（667ms / 28 会话） | 文件级摘要缓存（mtime+size）+ 5s 列表 TTL + **轻量摘要读取**（跳过 99% 无关行，不再把大日志解析成常驻对象）；扫描后常驻内存 0.6MB |
| P2 | sessionId 可穿越（`..\<ws>\<sid>`） | 白名单 `[A-Za-z0-9._-]` + 拒绝 `..` + 解析后校验仍在 sessionsRoot 下 |
| P2 | host 可配 0.0.0.0、无 Host 头校验 | 只接受回环地址（127.0.0.1/localhost/::1），并校验 Host 头（非回环 403） |
| P2 | 静态路径前缀判断偏弱 | 白名单路由（index.html / app.js / style.css）+ `startsWith(PUBLIC_DIR + sep)` |
| P2 | 缺 env 时回退相对路径 | 改 `os.homedir()`，取不到就显式报错 |
| — | 前端 `esc` 未转义单引号 | 补 `&#39;` |

## 打包 / 发布到插件市场

本包同时声明了两半，属于一个标准 DSH 组合包（bundle）：

```json
"dsh": {
  "bundle": { "patch": "./cordis.patch.yml" },
  "client": { "platform": "web", "inject": ["@deepseek-ai/dsh-client-ui-primitives"] }
}
"exports": { ".": "./lib/index.js", "./client": "./lib/client.js", "./server": "./lib/server.js", "./cordis.patch.yml": "./cordis.patch.yml", "./locale/*.json": "./locale/*.json", "./icon": "./icon.svg", "./package.json": "./package.json" }
```

发布步骤：

1. 推送 GitHub 仓库后，在仓库页面添加 topic `dsh-plugin`。
2. `npm login` 后执行 `npm publish --access public`（包名 `dsh-team-console`；后续改代码先用 `npm version patch` 递增版本，npm 不允许覆盖已发布版本）。
3. 满足社区目录的仓库年龄要求后，fork `awesome-dsh-plugin/awesome-dsh-plugin`，新增 `data/plugins/wulvfeng__dsh-team-console.yml`（模板已放在本仓库 `community/data/plugins/`），提交一个只含该文件的 PR。
4. 用户即可在市场搜索「团队控制台 / Team Console」，或命令行输入 `dsh plugin --profile web add dsh-team-console`。

DSH 没有内置官方索引；社区目录生成的索引会被多个市场引用，也可以自己托管一份 JSON 索引并在市场「发现」页添加 URL。仅本地开发时才需要 `node install.mjs` 的 `link:` 方式。

展示素材：`locale/en.json`、`locale/zh.json` 提供插件管理器标题/描述，`icon.svg` 为包内图标，`assets/icon-512.png` 供社区市场卡片使用，README 为市场详情页内容。

## 视觉与主题（0.9.1 重做）

- **自动跟随宿主主题**：面板全部使用 DSH 的 `--dsw-*` 设计令牌（背景层 / 文字层级 / 边框 / 品牌色 / 状态色 / 字体），浅色与深色由宿主切换，**插件本身没有主题开关**；强调色、描边、阴影都是从同一个令牌派生（`color-mix`），不会出现第二种「撞色」。
- **独立网页版**（`start.bat`）：`color-scheme: light dark` + `light-dark()` 调色板，跟随系统深浅色，无切换按钮。
- **一套克制的设计语言**：只用一个强调色（indigo），其余全部是中性灰阶；层次靠「表面／描边／极轻阴影／留白」表达，不再靠渐变堆叠。圆角统一 8 / 10 / 14 / 18，字号统一 10 / 11 / 12 / 13 / 14 / 22，间距走 4·6·8·10·12·14·16·20·24 的节奏。
- 结构：52px 顶栏（品牌 / 团队选择 / 实时状态胶囊）→ 296px 指挥栏（总览入口、智能体名册、请求与任务树）→ 右侧会话流（正文限宽 860px，长段落更好读）。
- **团队指挥中枢**：主视觉是一张带极光渐变与细网格的 Hero，下面接 4 张指标卡、智能体集群卡（悬停抬升 + 品牌描边）与任务矩阵；总览不再被挤在 820px 的窄栏里，而是铺满内容区。
- 细节：气泡 16px 圆角带小切角、代码块独立深色油墨面、步骤列表编号圆环 ↔ 状态色、`details` 箭头旋转、`focus-visible` 焦点环、骨架屏流光、细滚动条、长文本自动换行不横向溢出。
- 适配：≤900px 单列（指挥栏变成横向可滚动条带，隐藏次要元信息）；≤600px 隐藏品牌徽标与时钟、指标卡改单列，页面不产生横向滚动。
- 无障碍：所有交互控件有 `:focus-visible` 焦点环，`prefers-reduced-motion` 下动效全部关闭。

### 0.9.5 — 安全与健壮性修复

以安全、并发与异常路径为主的一轮修复（不新增依赖，双端行为保持一致）：

- **CORS 收紧**：只对回环 Origin 回显 `Access-Control-Allow-Origin`，任意网站不再能跨源读取本机会话数据；同时严格校验 Host 头与 HTTP 方法。
- **端口/配置校验**：非法 port / sessionsRoot / maxAgeDays 走显式回退或启动期报错；`port: 0` 由系统分配后回写真实端口；插件启动失败不再把异常抛给宿主。
- **增量读取**：只读取上次之后的**新增字节**（纯文本与 zstd 都不再整文件读），源字节缓存超出预算时淘汰旧缓存，避免长会话下内存与磁盘 IO 膨胀。
- **成员 stale 标记**：成员超过 10 分钟无新事件时活动标签显示「（10 分钟无新事件）」并视为非活跃；session-tree 兜底路径的阶段同步改为 inactive。
- **任务板一致性**：依赖的任务被删除后，pending 任务恢复 ready 并标注「（已删除）」；团队列表按 lead 去重；非团队会话返回 404。
- **缓存隔离**：sync 扫描先执行时不再污染 async 的 session-tree 兜底结果；`gzip;q=0` 的客户端不再收到 gzip 响应。
- **启动器诊断**：端口被其它程序占用时提示换端口并退出 2，已有实例在跑时直接给出地址退出 0。
- **面板健壮性**：断连状态可见、切换团队时选择器刷新、轮询同一时刻只跑一轮且请求 8s 超时放弃（不会堆叠请求）。
- **安装器**：`install.mjs` 现在同时注册 `dsh.profile.bundles`（修复装完 DSH 不加载插件的问题），并补上参数校验、原子写入与失败回滚。

验收：`node tools/verify.mjs` 71 项 + `node test/regression.mjs` 13 项全绿。

  - 「**分配的任务**」：淡蓝气泡（左侧"我"头像），就是我当初发给他的原文任务书，长文本默认折叠；
  - 「**他的回复**」：灰色气泡（左侧他的头像），他回报给我的结论，默认折叠可展开；
  - 「**怎么做的**」：工具调用步骤条，绿=成功、红=失败。
- 这样"我给他说什么 / 他回我什么 / 他做了什么"三件事用颜色和位置区分开，不用再翻会话流。
